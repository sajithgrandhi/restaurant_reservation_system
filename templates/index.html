Every booking is stored directly as a validated document in MongoDB restaurant_db.reservations.

MongoDB Integrity Rules

  • JSON Schema Validation: MongoDB enforces strict types, non-null values, valid email regex, and positive integers for table & guest counts.
  • Double-Booking Prevention: Overlapping time intervals on the same table are strictly rejected via $expr interval comparison.
  • BSON Date Values: Dates are stored as native BSON Date objects, enabling fast $gte and $lt range indexing.
  • Compound Index: (table_number, reservation_time) index guarantees sub-millisecond conflict checks.

MongoDB Inspection Commands

Verify documents and collection validation using mongosh or MongoDB Compass.

# 1. Connect via mongosh
mongosh "mongodb://localhost:27017/restaurant_db"

# 2. View collection stats and document count
use restaurant_db
db.reservations.countDocuments()

# 3. View all active indexes
db.reservations.getIndexes()

# 4. View JSON Schema validation rule
db.getCollectionInfos({ name: "reservations" })[0].options.validator

# 5. Query upcoming bookings using BSON date range
db.reservations.find({
  reservation_time: { $gte: new Date() }
}).sort({ reservation_time: 1 }).pretty()

# 6. Run Status Aggregation in shell
db.reservations.aggregate([
  { $group: { _id: "$status", count: { $sum: 1 }, guests: { $sum: "$guests" } } },
  { $sort: { count: -1 } }
])
